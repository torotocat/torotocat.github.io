一块焊死的 NAND：M1 MacBook 救砖全过程，最后修的是硬件

发表于2026-09-13|更新于2026-09-13|生活
|评论数:

这台 MacBook 的结局，是在维修店里的。但走到那个结局之前，我们把能试的软件路线全试了一遍——而每一条路，最后都撞在同一块焊死的 NAND 上。

这篇文章按时间顺序记：先讲症状，再讲每一步为什么失败，最后讲为什么”修硬件”不是放弃，而是唯一的出口。

一、症状与第一个要打破的错觉

最初的描述是这样的：macOS 磁盘坏了，买了一块外置硬盘，想把系统装上去。

这里第一个要分清的是三种完全不同的”坏”：

症状 性质 后果
开机问号文件夹 只是找不到启动系统 盘大概率还能读，先抢救数据
能进恢复模式、磁盘工具里能看到内置盘 引导/系统卷坏了 可以试重装
咔咔响 / 磁盘工具里根本看不到 物理坏 数据只能找专业机构

还有一条定心丸要先吃：磁盘坏了 ≠ 电脑坏了。M1 的主板、芯片、固件是独立的，内置盘坏只影响存储。当时的判断依据是”DFU 还能刷进去”，说明芯片是活的。

而”装到外置盘”这件事在 M1 上理论上真的可行，原因是一条很多人不知道的硬件事实：

Apple Silicon 的启动界面（长按电源键出来的那个启动选项）写在芯片固件里，不依赖内置硬盘。

所以内置盘坏了，机器仍然能进启动选项、仍然有能力从外部介质引导——这是后来所有尝试的前提。

二、第一次尝试：恢复模式直接装到外置盘

不需要第二台 Mac，理论上四步：

  1. 接上外置SSD（USB-C/雷电口；机械盘装系统会卡到怀疑人生）
  2. 开机长按电源键 → 点齿轮「选项」进恢复模式。内置盘的本地恢复分区读不出来，它会自动联网恢复，需要先连 Wi-Fi，等它下载恢复镜像
  3. 磁盘工具里抹掉外置盘：APFS + GUID 分区图
  4. 「安装 macOS」→ 点「显示所有磁盘」→ 选外置盘 → 装（下载完整系统 10GB+，网速快也要半小时以上）

常见的坑也都在这儿：启动选项里看不到外置盘（换线/换口，或去「启动安全性实用工具」允许从外部介质启动）、安装时找不到外置盘（没抹成 APFS+GUID）、装完卡住（长按电源键手动选启动盘）。

结果是：走到最后阶段失败。

三、撞墙的位置暴露了病根

这个失败点很关键。外置盘安装 macOS 并不是”只往外部硬盘写”——安装器在最后阶段仍然要往内置盘写恢复分区和固件。也就是说：

只要写内置盘的动作为真，内置 NAND 一坏，安装就必然挂。

这一步之后，”磁盘坏了但机器好好的，装外置盘就复活”这个乐观假设，已经站不住了。

四、分水岭：revive 能过，restore 必挂

下一步是 DFU 刷机（Apple Configurator / Apple Devices，需要另一台 Mac 用 USB-C 线连）。DFU 里有两个不同的动作，它们的结果不一样，而这个差异就是全场最重要的诊断信号：

动作 做什么 写入量 结果
revive 只重刷系统卷固件，保留数据 小 ✅ 能过
restore 全盘擦除 + 完整重写（系统卷 + 数据卷 + 恢复卷） 大 ❌ 报错

机制上说得通：内置 NAND 有坏块或寿命磨损时，小量写入还能绕过去，全盘完整重写就必然撞上坏块，于是中断报错。同时 revive 能过也反过来说明：链路、芯片、线材都没问题——线材不背锅。

当时的错误码是 1113。查证结果：报错全文是 AMRestoreErrorDomain error 1113 - Failed to handle message type StatusMsg，即恢复流程中设备无法继续处理主机的状态消息、通信中断。扒到的社区同款案例（4 条，全是 M1）：

案例 结果
MacBook Air M1 走 DFU 报 1113 评论：AC 刷不了，只能送 Apple Store
MacBook Pro M1 升级失败转 DFU 报 1113 典型是线材/固件写入失败，排除线口后指向逻辑板/存储
M1 Mac mini 升级全失败报 1113 楼主最终定位为 M1 自身固件问题，Intel 主机修不了
同类 error 6（同一个 StatusMsg 家族） revive 失败 → restore 也失败，结论送检

1113 和 error 6 是同一个错误家族，社区里这类错误走到最后，无一例外指向硬件层面或送修。

到这里证据链就闭合了：

  1. revive 能过 → 链路、芯片 OK
  2. restore 报 1113 → 刷固件写不进内置存储
  3. 外置盘安装最后阶段失败 → 要写内置恢复分区/固件
  4. 系统层面已判定内置盘”不是 macOS”

五、读日志：系统其实早就告诉你了

恢复模式的安装日志里能翻到这两行（它们才是最有信息量的）：

disk3s1 Macintosh HD 是内置盘的系统卷——启动器在上面找不到 bootcaches.plist，于是判定它”不是 macOS”，也就是系统已经不完整/读不出来。同一份日志里其余的行大多是恢复模式的正常噪音（dmg booted but not physical media、System doesn't have bridgeOS、KeyRecoveryAssistant 认证成功但内部没有 FileVault 卷所以直接退出）。

顺带一个好消息式的信息：KeyRecoveryAssistant: Has Authenticated: YES——设备激活状态正常，没有激活锁问题。

六、时间窗：能进恢复模式 = 最后一个读盘窗口

这是整件事里唯一有时间压力的一步。能进恢复模式说明磁盘还能被系统看到，这是最后一个读数据的窗口：

  • 磁盘工具里看 Macintosh HD 能不能挂载、能不能看到文件
  • 能读 → 终端里把用户目录整份拷到外置盘
  • 挂载就报 I/O 错误 / 拷到一半卡死 → 停手，别再试。反复读坏 NAND 只会更坏

七、仅剩的两条软件路线，都写在这里

软件层面其实还有两条路，最后一条是”不碰坏盘”的：

① asr 跨机克隆（唯一不写坏盘的招）

asr（Apple Software Restore）是苹果自带的整盘克隆工具，把一台 Mac 的整个系统原样复制到另一块盘。它的价值在于：全程在另一台好 Mac 上操作，坏盘根本不参与，所以不会中途失败。

但有一关过不去：Apple Silicon 的 macOS 系统卷是跟具体哪台机器绑定的（personalized）。装系统时系统卷签名会跟这台机器的芯片、启动安全策略绑定，你在 A 台克隆出来的系统是”签给 A 台”的；插到坏的那台上，安全启动链校验签名对不上，大概率直接拒载。有小概率成功（同型号、系统版本老），但本质是赌。失败成本≈0，所以有条件值得一试。

② UEFI-only + 系统全放外置盘（Asahi 那条路）

思路是内置盘只写一个引导器、系统完全放外置盘。这条有真实先例（Asahi 官方仓库 issue #96，有人做过完全一样的方案）：

  • 第一坑：U-Boot 不会自动从外置盘引导，直接掉进 grub rescue
  • 解法一：外置盘的 FAT32 分区里放 /efi/boot/bootaa64.efi——这是 UEFI 规范里可移动介质的回退路径，放别处不认
  • 解法二：修 GRUB 配置里的分区 UUID——外置盘每次格式化 UUID 都会变，配置对不上就找不到系统

而官方态度很直白（Asahi 创始人 marcan 原话）：external install 只是给开发者实验用的，不支持终端用户，专家模式本来就是会坏的。

**这条路的前置条件同样是”内置盘还能被写”**——而这恰恰是这台机器已经不成立的。所以最后它连试的机会都没有。

八、结论：为什么”救砖”在这台机器上不成立

把上面的东西合起来，是一句不太好听的话：

M1 的 SSD 是焊死在主板上的，而且启动链、恢复分区、固件更新这几件事全都要碰内置盘。内置盘一坏，”软件救砖”这个选项就不存在了。

外置盘能做的只是应急：就算某天真从外置盘跑起来了，系统大版本更新、固件更新仍然会失败（这些操作会碰内置恢复分区），而且不排除哪天固件更新把系统直接搞挂。

所以决策变成纯经济账：

方案 价格 判断
官方换主板 3000+ 对 2020 款的机器，不值
第三方换 NAND / 搬板 1500～2500 和二手残值（2000～4000）比
当尸体卖 800～1500 止损线
专业数据恢复（NAND 级搬板） 2000～5000+ 只在这台机器里有”值这个价”的数据时

判据一句话：修价 ≥ 二手价，就直接买二手，别修。

九、送修实录：最后修的是硬件

送修之后的经过，比前面所有技术分析都更有教益。

第一轮：换硬盘（NAND），800。

师傅换完 NAND，测试了一天没问题，交机。结果第二天又开始重启。

第一轮判断为什么错？ 有两个可能：硬盘不是真正的病根，或者换上去的料本身有问题。但更值得注意的是症状形态——“测一天才犯病”恰恰是硬件虚焊最典型的特征：

开机后温度慢慢升高，焊点热胀冷缩一分离就断电重启，凉下来又正常。

这也顺手排除了另一个自我怀疑：”是不是我把别的用户 ID 刷进去了？”——不是。软件/固件层面的问题（Apple ID、个性化数据）表现是进不去系统、白苹果、激活锁弹窗，**它不会”正常跑一天然后重启”**。

更硬的一条证据是内核崩溃日志（panic）：系统报告里能翻到一条 15:17 的 panic。这说明重启不是玄学、不是电池、不是温度，而是硬件层把系统直接干崩了。而且 panic 报告会写明是哪块硬件干崩的——nvme / ANS2 / sks 字样指向存储，SoC/板层相关字样指向 CPU 或主板。看这一个文件，比听任何人的推测都强。

当时的报告里还能读到几条有用信息：机器能进系统（说明换的 NAND 能引导、能跑，不是彻底废）、序列号 F 开头（2020 年产）、跑 15.6.1。

第二轮：CPU / 板层，还是 800。

师傅的判断是”应该是 CPU 或者板层断线”，并明确了一句：”如果是 CPU 本身的问题导致的故障，动了有不开机的风险“，以及”如果万一黑屏完全没反应，这个我们不负责”。

这句话要听明白：这台机器现在不是砖，是半砖——能开机、能进 DFU、只是重启。赌输了才是全砖，连 DFU 都进不去，这 800 块也白花。所以”反正也是砖了，修好血赚”这个心态可以，但必须知道代价是可能变得更死，而不是维持原样。

价格本身不算黑：BGA 重植 CPU 或板层飞线，行情普遍 400～1500，800 属于正常区间。而且两轮都是 800，没有坐地起价。

修之前值得问清楚的三件事（这次也这么做了）：

  1. 是重植（reball）还是只加焊（reflow）？重植更稳，加焊容易返修
  2. 修完保多久？一般至少保 3 个月
  3. 让他修完连续测试 3 天再交机——虚焊的机器跑一天才犯病，测一天不够

另外可以让他顺带查一下 T2 芯片（部分 2020 款机型），T2 虚焊和 CPU 症状经常一模一样，别只盯着 CPU。

最坏情况的兜底也算了：真黑屏了就拆件卖，屏幕是大头（Air M1 屏幕约 800～1200，整机拆件大概能回 1500～2500）。修的价值仍然大于拆——但要是修坏了，记得让师傅把尸体留着，拆件还能回点血。

十、复盘：五条能直接复用的经验

  1. revive 能过、restore 必挂 = 存储坏了。 这是最快的判别法，比换线、换口、重装快得多，而且不冤枉线材。
  2. 在 M1 上，”装到外置盘”不是万能逃生门。 它的前提是内置盘还能被写（恢复分区/固件那一步）。内置盘一坏，外置盘方案连起跑线都上不去。
  3. 能进恢复模式的那段时间，是唯一的数据窗口。 挂载报 I/O 错就立刻停手，别为了多拷几个文件把盘读死。
  4. panic 日志是病根的直接证据。 崩溃能留下日志说明系统活着活崩的，报告里写明了是哪块硬件；拿它去跟维修师傅对话，比”我感觉是硬盘”有效得多。
  5. 报价永远和残值一起算。 官方 3000+ vs 二手 2000～4000，账一算就知道该修还是该换；任何一方单独看都会算错。

这台机器的后续：截至写这篇的时候，它还躺在师傅那儿等 CPU 重植的结果。修好了我再来补一段。
